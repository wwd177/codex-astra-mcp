# Gemini 4 × GPT-6.2 Astra 极致深度零风险双核协作规范（v1.2.1）

本技能基于常驻热连接 `codex-astra v1.2.1` 引擎设计，默认将 **GPT-6.2 Astra** 拉满至 **`max` 极致推理强度**（并开放 `ultra` 档按需调用），确保 **Antigravity 主控（1M 上下文主工程师）** 与 **GPT-6.2 Astra（只读红队深度审查员）** 实现高质量交锋、零双写风险、杜绝互相附和（Anti-Sycophancy）。

---

## 1. 核心角色与安全边界

- **Antigravity 主控（你，主工程师）**：
  - 负责 1M 大上下文代码库探索、精准代码切片提取、整体方案落地、文件写入与终端测试验证。
  - **唯一拥有写文件与终端修改权限的一方**，杜绝双写冲突。
- **GPT-6.2 Astra / Sol（经由 `codex-astra` 常驻只读热通道）**：
  - 严格运行在三重锁死的 `read-only` 沙箱，已自动隔离全局重型外部 MCP 与桌面插件。
  - 负责极致深度的独立盲评、反方挑刺、数理/并发边界推演与真实 Git Diff 缺陷捕获，永不修改本地文件。

## 2. 推理强度选择策略（默认满血 `max`）

| 协作场景 | 推荐 `model` | 推荐 `effort` | 是否传 `cwd` |
| :--- | :--- | :--- | :--- |
| **标准架构盲评 / 代码红队挑刺 / Git Diff 审计（默认）** | `gpt-6.2-astra` | **`max`（默认，无需显式降档）** | 切片完整时**省略 `cwd`**；仅 Diff 或需核验局部文件时传 |
| **超复杂多步推演 / 需自动委派子推演的终极难题** | `gpt-6.2-astra` | **`ultra`** | 按需传入工作区路径 |
| **用户明确要求“快问/省时/轻量”的语法或简单复核** | `gpt-6.2-sol` 或 `gpt-6.2-astra` | `low` / `medium` / `high` | **不传 `cwd`**（直接喂切片） |

> **注意**：严禁未经用户要求擅自把默认的 `max` 降档为 `medium`/`low`；除非用户明确指示追求极速快问，否则保持省略 `effort`（自动走服务端默认 `max`）或显式传入 `max` / `ultra`。

## 3. 三大标准协作流水线（单轮直达优先，拒绝串行打乒乓）

### 流水线 A：单轮盲评与红队决策（Single-Round Blind / Redteam）
适用场景：技术选型、架构拍板、方案对比。
1. **本地切片与独立判断**：你先利用自身工具读取相关代码（同一回合批量读取），在内心明确你的方案，提炼出**客观背景、约束条件与核心代码切片**。
2. **单轮直调（二选一）**：
   - **需无偏盲评时**：调用 1 次 `astra_ask`（默认 `max`，不暴露你的倾向结论，省略 `cwd`），让 Astra 独立给出最优解与潜在雷区；
   - **已有明确方案需挑刺时**：直接调用 1 次 `astra_redteam`（传入你的精炼方案与代码切片，默认 `max`），直接获取 `VERDICT` 与 `P0/P1` 反例。
3. **当场收敛或追问**：
   - 吸收有事实依据的修正直接落地；若存在核心权衡冲突，禁止和稀泥，直接用对比表向用户呈报 `DEADLOCK`。
   - 仅当关键事实需二次交锋时，传入上轮返回的 `thread_id` 热续接 `astra_ask`（命中 Prompt Cache，最多追问 1 轮）。

### 流水线 B：构建 → 深度 Diff 审计 → 闭环（Deep Build & Diff Review）
适用场景：功能实现、Bug 修复、模块重构。
1. **实现与自测**：你在工作区完成代码修改并跑通基础验证。
2. **单次深度审计**：
   - Git 仓库改动：调用 `astra_review_diff`（传 `cwd` 与 `focus`，默认 `max`，未提交改动优先走常驻热通道）；
   - 非 Git 目录：调用 `astra_redteam`（传入改动前后关键切片，默认 `max`，省略 `cwd`）。
3. **事实核验与收敛**：对每条 `P0/P1` 意见回读真实代码核验真伪，修复真缺陷并验证通过即交付（最多复审 1 次，防循环拖延）。

### 流水线 C：疑难 Bug 双盲排错（Dual-Blind Root Cause）
适用场景：偶发竞态、隐蔽状态污染、跨进程异常。
1. 提取最小复现条件、报错堆栈与核心函数切片（控制总输入精炼聚焦）。
2. 调用 1 次 `astra_ask`（`model: "gpt-6.2-astra"`, 默认 `max` 或 `ultra`，附完整切片），要求其直接输出 **Top 3 根因假设 + 最小证伪实验**。
3. 结合你的第一假设取并集，直接用终端命令/单测快速证伪并完成最小侵入修复。

## 4. 质量与效率黄金铁律

1. **切片投喂免扫盘（把算力全花在深度推理上）**：
   - 只要你已读取相关代码，**务必把核心代码切片（含文件名与行号）直接塞进 `prompt` / `proposal`，并省略 `cwd` 参数**！省略 `cwd` 会自动挂载空只读隔离目录并禁止 Astra 启动 PowerShell 扫盘，把 `max` 推理预算 100% 集中在深度逻辑推演而非磁盘遍历上。
2. **唯一结构化裁决字段**：
   - 红队与 Diff 审计首行固定输出 `VERDICT: LGTM` / `VERDICT: NEEDS_FIX` / `VERDICT: DEADLOCK`，严禁正文中重复出现干扰判定。
